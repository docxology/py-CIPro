# CICY data provenance and reproducibility

## Source and scope

The explorer reads `CIProData/Cicy3` from the published CIPro v1.0 release ZIP. This textual member contains 7,890 configuration records in the classical CICY threefold list compiled by Candelas, Dale, Lütken and Schimmrigk. The release asset is separate from the upstream Git tree at its tag. Pin the release bytes when comparing results across checkouts. [CIPro v1.0 release](https://github.com/JamesGray-Physics/CIPro/releases/tag/v1.0) · [Original classification](https://www.sciencedirect.com/science/article/pii/0550321388903525) · [Oxford CICY list](https://www-thphys.physics.ox.ac.uk/projects/CalabiYau/cicylist/index.html)

| Artifact | SHA-256 |
| --- | --- |
| `CIProPackage.zip` | `39223db768893c958be776071bcbf86d0ef5692f92e1ab153ef1ce8d3440dd53` |
| `CIProData/Cicy3` | `e6e61888281efc7bf4d0d1bd76b62c18c764f1028f17924b9ffe8edce9d6ec17` |

The catalog loader validates both hashes, the member syntax, and the expected one-based `Num` sequence. It reads the pinned Wolfram text as data, with no Wolfram evaluation, and checks rectangular degree matrices, positive inferred ambient dimensions, threefold dimension, and the stored Euler identity. Only this one dataset is parsed by the explorer. The other seven upstream collections remain available through CIPro's Wolfram `Data` function on a compatible kernel. [Catalog source](../src/py_cipro/catalog.py) · [CIPro paper, Appendix C](https://arxiv.org/html/2606.27588v1#A3)

## Fields and interpretation

| Explorer field | Released field or derivation |
| --- | --- |
| `id` | Archived `Num`, a one-based configuration identifier for this release. |
| `h11`, `h21` | Archived `H11`, `H21`. Use the product flag to interpret the zero placeholders. |
| `euler` | Archived `Euler`. Every stored row satisfies `Euler = 2 × (H11 − H21)` arithmetically. |
| `favourable` | Archived `Favour`. A favourable configuration has second cohomology generated by classes descending from the ambient factors. |
| `product` | Archived `IsProduct`. The 22 product rows in this release carry the stored Hodge pair `(0, 0)`. Treat it as a placeholder for those rows. |
| `configuration` | Archived `Conf`. Rows are projective factors, columns are defining equations, and entries give degrees. |
| `ambient_dimensions` | Derived from the Calabi–Yau row-sum condition, `sum(row) - 1` for each ambient factor. |

The loader retains the archive's order. The explorer can show different configurations with the same Hodge pair or Euler number. Counts describe these catalog records and their stored fields. A pair of Hodge numbers does not identify a configuration or an isomorphism class. Favourability refers to a presentation. Some non-favourable presentations admit another, favourable presentation. [CICY classification](https://www.sciencedirect.com/science/article/pii/0550321388903525) · [Green, Hübsch and Lütken on Hodge numbers](https://doi.org/10.1088/0264-9381/6/2/006) · [Anderson et al. on favourable presentations](https://arxiv.org/abs/1708.07907)

A scatter point represents a stored pair and can represent many configurations. The Euler distribution counts configurations, so each record contributes once independently of how many share its Hodge pair. For a Hodge analysis of non-product threefolds, use the product flag to exclude those 22 placeholders and report the resulting denominator. The full release has 266 distinct stored pairs including the placeholder. The 7,868 non-product rows have 265 distinct pairs. This agrees in cardinality with the historical result of Green, Hübsch and Lütken; the arithmetic check does not reconstruct their Hodge-number calculations. [Historical Hodge calculation](https://doi.org/10.1088/0264-9381/6/2/006)

## Reproduce the archive counts

This script runs from a py-CIPro Python environment without an activated Wolfram kernel. It uses the same checked records as the dashboard. See the [manuscript build guide](manuscript.md) to reproduce the publication figures and the PDF.

```python
from collections import Counter
from py_cipro.catalog import get_catalog

catalog = get_catalog()
rows = catalog.records
non_products = [row for row in rows if not row.product]
stored_pairs = {(row.h11, row.h21) for row in rows}
non_product_pairs = {(row.h11, row.h21) for row in non_products}
euler_counts = Counter(row.euler for row in rows)

assert len(rows) == 7890
assert len(non_products) == 7868
assert len(stored_pairs) == 266
assert len(non_product_pairs) == 265
assert sum(row.favourable for row in rows) == 4874
assert all((row.h11, row.h21) == (0, 0) for row in rows if row.product)
assert (min(euler_counts), max(euler_counts)) == (-200, 0)
assert euler_counts.most_common(3) == [(-32, 613), (-40, 547), (-24, 530)]
assert all(row.euler == 2 * (row.h11 - row.h21) for row in rows)
print(catalog.dataset, catalog.release, catalog.sha256, catalog.member_sha256)
```

| Reference case | Archive ID | Degrees by ambient row | Ambient dimensions | Archived `(h11, h21, Euler)` |
| --- | ---: | --- | --- | --- |
| Bicubic threefold | 7884 | `[[3], [3]]` | `[2, 2]` | `(2, 83, -162)` |
| Quintic threefold | 7890 | `[[5]]` | `[4]` | `(1, 101, -200)` |

The bicubic and quintic each have one equation of degree equal to the corresponding ambient anticanonical degree. The expected complex dimension is three in both cases. Their Euler values can also be derived from the top Chern class by adjunction and integration over the ambient hyperplane classes. The archived Hodge fields are data, while the dimensional and Chern-class calculations are independent mathematical checks. [CIPro geometric conventions and Chern polynomials](https://arxiv.org/html/2606.27588v1#S2)

## Reproduce a live calculation

Use a suitably licensed, activated Wolfram kernel as described in the [backend guide](wolfram-api.md). Start a fresh client for a qualification run and pass an association containing the defining inputs. Passing archived derived keys back to the dispatcher can reuse stored values.

```python
from py_cipro import CIPro
from py_cipro.catalog import get_catalog

catalog = get_catalog()
with CIPro() as ci:
    for number in (7884, 7890):
        row = catalog.record(number)
        geometry = {"Conf": row.configuration, "DimPs": row.ambient_dimensions}
        result = ci.property(geometry, ["CIDim", "CY", "Euler"])
        assert result["CIDim"] == 3
        assert result["CY"] is True
        assert result["Euler"] == row.euler
```

The dashboard's optional kernel request uses the same input construction and three allowlisted properties. The UI labels effects of the live calculation independently of the archive. The `CY` property checks the configuration's anticanonical row equality. Questions of smoothness for particular defining equations require additional calculations. For generated equations or finite-field singularity checks, record the equations or the seed and coefficient options, the field characteristic, and the interpretation of any modular result. [CIPro paper, Section 2.2](https://arxiv.org/html/2606.27588v1#S2.SS2)

For durable evidence, record the following with each result.

- Wrapper commit, release tag, release archive hash, and dataset member hash if applicable.
- Dataset name and configuration IDs, exact association inputs, requested function or dispatch keys, and every relevant option.
- Wolfram version, system ID, runtime mode, and any random seed or concrete generated input. For a dataset-only calculation, record the Python version and parser revision instead.
- Status and messages, along with the exact WXF bytes for symbolic results or typed JSON for bounded scalar results.
- Filter predicates, inclusion or exclusion of products, and counting convention for figures. Include the figure generation command and commit.

Offline catalog tests check the byte binding and record invariants. HTTP tests exercise browse mode and the narrow kernel request boundary using a test double. Mathematica-specific function execution, timings, and optional binary dataset compatibility require separate observed results.
